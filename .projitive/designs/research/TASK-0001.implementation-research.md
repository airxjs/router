## Code Architecture and Implementation Findings

- `source/router.ts` - Core router implementation (350+ lines):
  - `source/router.ts#L1-L10` - Module docstring and usage examples
  - `source/router.ts#L18-L56` - Type definitions: BaseRoute, RouteComponentProps, PathRoute, RedirectRoute, Route
  - `source/router.ts#L58-L68` - Type guards: isRedirectRoute, isPathRoute
  - `source/router.ts#L70-L87` - useRouter() hook - injects History from provider context
  - `source/router.ts#L89-L109` - RouterProps interface
  - `source/router.ts#L111-L270` - Router component implementation:
    - Matcher cache (matcherMap) using path-to-regexp
    - matchRoute() recursive function for nested route matching
    - handleHistoryUpdate() for history change handling with redirect support
    - createRouteElement() for building component tree
  - `source/router.ts#L272-L285` - Path utilities: isAbsolute, joinPaths
  - `source/signal.ts#L1-L80` - Signal utilities for reactive state (createWatch, createState, createComputed, isState)
- `source/path.ts` - Path normalization utilities (referenced but content not yet reviewed)
- `source/router.test.ts` - Test suite (not reviewed in detail)

### Key Architecture Decisions

1. **Signal-based reactivity**: Uses native Signal API (or polyfill) for reactive state management
2. **Provider/injection pattern**: Router provides History via airx's provide/inject mechanism
3. **Path-to-regexp**: Compiles routes to regexp matchers, cached in matcherMap
4. **Recursive matching**: matchRoute() recursively processes nested routes
5. **Redirect handling**: Redirects are processed during history updates, supports relative and absolute paths

### External Dependencies
- `history@^5.3.0` - History management (createBrowserHistory, createMemoryHistory, createHashHistory)
- `path-to-regexp@^6.2.1` - Path matching (pathToRegexp, regexpToFunction)
- `airx@^0.7.1` (peer) - Component framework (AirxComponent, createElement, provide/inject)

### Limitations (from README)
- Must be used within airx component context
- Single Router instance per app only
- No built-in guards (auth/permission handled externally)
- Paths must start with `/` for root-relative matching
- Requires signal-polyfill or native Signal support
